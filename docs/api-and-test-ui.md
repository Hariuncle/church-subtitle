# 운영 API와 로컬 테스트 UI 구분

이 프로젝트에는 교회 방송 시스템이 붙을 **운영 WebSocket API**와, 개발 중 결과를 눈으로 확인하기 위한 **로컬 테스트 UI**가 함께 들어 있다. 둘은 같은 `/ws/captions` 프로토콜을 사용하지만 입력 출처와 표시 책임이 다르다.

| 구분 | 운영 WebSocket API | 로컬 테스트 UI |
| --- | --- | --- |
| 목적 | 교회 방송 오디오를 받아 자막 이벤트 제공 | 저장된 예배 PCM과 YouTube 영상을 맞춰 품질 확인 |
| 오디오 입력 | 방송 시스템이 보내는 live `24 kHz / 16-bit / mono PCM` | 서버에 준비한 전체 PCM을 현재 영상 위치부터 HTTP Range로 읽음 |
| 자막 출력 | 세션 동안 모든 `CaptionUpdate`의 `partial`/`final`/`status`를 연속 전송 | 최신 텍스트를 줄바꿈 결과 기준 최대 2개 시각적 줄로 투영 |
| 기록·줄바꿈 | API에는 **2줄 제한 없음**. 소비자가 누적, 교정, 줄바꿈 정책을 결정 | 오래된 윗줄을 숨기고 최신 두 시각적 줄만 표시 |
| 세션 종료 | 정확한 `{"type":"end"}`, 연결 해제 또는 오류 | 사용자의 `중지`, 영상 끝, 연결 또는 동기화 오류 |
| API 키 | 서버 프로세스에서만 사용 | 브라우저가 읽거나 전송하지 않음 |

## 운영 WebSocket API 계약

현재 PoC 서버는 `ws://127.0.0.1:5287/ws/captions`에서 한 세션을 받는다. 이 localhost 제한은 현장 연동 전 검증용 보안 경계다. 다른 장비에서 접근하는 운영 배포 단계에서는 기존 방송망 구조에 맞춰 인증, TLS, 접근 제어를 별도로 설계해야 한다.

클라이언트 전송 순서는 다음과 같다.

1. 연결 직후 UTF-8 텍스트 프레임 `{"type":"start","delay":"low"}`를 보낸다. `delay`는 `low` 또는 `medium`이다.
2. 헤더 없는 PCM을 binary 프레임으로 계속 보낸다. 권장 단위는 100ms인 4,800바이트다.
3. 정상 입력 종료 시 UTF-8 텍스트 프레임 `{"type":"end"}`를 보낸다.

서버는 `CaptionUpdate` JSON 텍스트 프레임을 연속으로 반환한다.

```text
CaptionUpdate
- sessionId
- sequence
- lineId
- revision
- text
- state: partial | final | clear | status
- provider
- emittedAtUtc
```

- `partial`: 같은 `lineId`의 진행 중 문장을 더 높은 `revision`으로 갱신한다.
- `final`: 해당 `lineId`의 확정 결과다. 운영 소비자는 이를 저장하거나 기존 행을 교체할 수 있다.
- `status`: 연결 및 종료 상태다. 자막 본문으로 취급하지 않는다.
- 단어 timestamp, confidence, 화자 정보는 모델이 제공하지 않으면 생성하지 않는다.

OpenAI 공급자의 내부 10초 commit은 자막 segment를 확정하기 위한 서버 구현 상세다. WebSocket 세션을 끝내지 않으며 클라이언트가 보낼 명령도 아니다. binary PCM이 계속 도착하는 동안 API도 계속 동작한다.

## 로컬 테스트 UI 계약

브라우저 화면은 운영 자막 송출기가 아니라 API를 시험하는 샘플 클라이언트다.

- YouTube iframe의 소리를 직접 캡처하지 않는다.
- `시작`을 누른 순간의 영상 위치를 전체 PCM 바이트 위치로 바꿔 파일 끝까지 실시간 속도로 전송한다.
- 두 개의 안정된 DOM 행에 최근 final과 현재 partial을 투영한다.
- 긴 문장이 각 DOM 행 안에서 여러 줄로 줄바꿈되어도 자막 무대는 정확히 두 line-height만 보여준다.
- 글자 크기를 줄이거나 말줄임표를 붙이지 않고, 넘친 오래된 윗부분을 숨겨 최신 두 시각적 줄을 남긴다.

따라서 UI에서 과거 문장이 사라지는 것은 API 데이터가 삭제되거나 전송이 중단된다는 뜻이 아니다. 실제 방송 자막 sink는 이 연속 이벤트를 받아 현장 시스템 규격에 맞게 2줄, 누적 기록, 파일 또는 별도 API 형식으로 출력하면 된다.
