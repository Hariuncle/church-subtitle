# 왼쪽 정렬 연속 2줄 자막 설계

## 목표

로컬 테스트 UI의 자막을 별도 행 두 개가 아니라 하나의 연속 문장으로 표시한다. 자막은 왼쪽 위에서 시작하고, 서로 다른 `CaptionUpdate` 조각은 강제 줄바꿈 없이 공백 한 칸으로 연결한다. 자연스러운 줄바꿈으로 세 번째 시각적 줄이 생기면 맨 위 한 줄만 화면 밖으로 밀어내고 아래의 최신 두 줄을 보여준다.

이 변경은 브라우저 테스트 UI의 투영 정책에만 적용한다. 운영 WebSocket API의 입력, 세션 수명, `CaptionUpdate` 메시지, `partial`/`final` 전달 순서는 변경하지 않는다.

## 표시 구조

- 기존 `caption-line-1`, `caption-line-2` 두 문단을 하나의 `caption-text` 문단으로 교체한다.
- `caption-text`는 정확히 두 line-height 높이이며 `overflow: hidden`을 사용한다.
- `text-align: left`로 왼쪽 정렬하고, 콘텐츠가 두 줄 이내일 때는 컨테이너의 왼쪽 위에서 시작한다.
- 글자 크기를 줄이거나 말줄임표를 붙이지 않는다.
- 자막 조각 사이에는 정확히 ASCII 공백 한 칸을 둔다. HTML 요소 사이의 블록 줄바꿈이나 `<br>`은 사용하지 않는다.

## 데이터 투영

- 기존 `lineId`와 `revision` watermark를 유지해 오래된 partial과 final 교정을 거부한다.
- final 조각과 현재 partial 조각에서 앞뒤 공백을 제거하고, 빈 조각은 제외한 뒤 `join(" ")`으로 하나의 문자열을 만든다.
- partial은 동일 `lineId`의 최신 revision으로 교체되며 final 뒤에 공백 한 칸을 두고 이어진다.
- partial이 final이 되면 같은 위치의 확정 조각으로 전환된다. 다음 final 또는 partial은 이전 텍스트 바로 뒤에 공백 한 칸으로 이어진다.
- UI 재투영에 필요한 확정 조각은 최근 64개로 제한한다. 이는 브라우저 메모리를 제한하기 위한 내부 버퍼이며 API 이벤트를 자르거나 누락시키지 않는다.
- 세션 시작 시 문단을 비우고, 세션 종료 후에는 마지막 화면을 유지한다.

## 한 줄씩 밀어내기

브라우저는 문단의 전체 연속 텍스트를 유지하며 앞부분을 문자열에서 삭제하지 않는다.

1. 새 자막 문자열을 `textContent`에 설정한다.
2. 브라우저가 계산한 `scrollHeight`와 고정된 두 줄 높이 `clientHeight`를 읽는다.
3. 넘침이 없으면 `scrollTop = 0`으로 유지해 왼쪽 위에서 시작한다.
4. 세 번째 줄이 생기면 `scrollTop = scrollHeight - clientHeight`로 이동한다.

줄 높이가 고정되어 있으므로 자연스러운 새 줄이 추가될 때 스크롤 오프셋도 한 line-height씩 증가한다. 그 결과 기존 둘째 줄은 새 첫째 줄이 되고 새로 생성된 셋째 줄은 화면의 둘째 줄이 된다. 별도 강제 줄바꿈이나 단어 단위 잘라내기는 하지 않는다.

한 번의 큰 revision이 여러 새 줄을 만들면 넘친 시각적 줄 수만큼 위쪽 줄을 이동해 최종적으로 최신 두 줄을 남긴다. 이는 각 줄을 순서대로 한 줄씩 밀어낸 것과 같은 결과이며 두 줄 전체를 한꺼번에 초기화하지 않는다.

## 문서 경계

- README와 `docs/api-and-test-ui.md`의 테스트 UI 설명을 단일 연속 문단과 한 줄씩 밀어내는 규칙으로 갱신한다.
- 운영 API 문서에는 응답이 계속 개별 `CaptionUpdate` 이벤트라는 점과 UI의 공백 결합·스크롤이 API 계약이 아니라는 점을 유지한다.

## 접근성 및 안전성

- 단일 자막 문단을 기존 `aria-live="polite"` 영역 안에 두고, 텍스트 삽입은 계속 `textContent`만 사용한다.
- 브라우저에는 OpenAI API 키, 원시 공급자 오류, 스택 추적을 노출하지 않는다.
- 사용자가 중지하거나 영상이 끝나기 전까지 오디오와 API 자막 이벤트는 기존과 같이 계속 흐른다.

## 테스트

- final 두 개와 partial 하나가 강제 줄바꿈 없이 공백 한 칸으로 연결되는지 검증한다.
- 조각의 중복 공백과 앞뒤 공백이 화면에서는 정확히 한 칸으로 정규화되는지 검증한다.
- 한 줄 또는 두 줄 분량에서는 `scrollTop`이 0이고 왼쪽 위 정렬인지 검증한다.
- 세 번째 시각적 줄이 생기면 `scrollTop`이 정확히 `scrollHeight - clientHeight`가 되어 맨 위 한 줄만 밀려나는지 검증한다.
- partial revision, final 교정, 빈 final, 세션 초기화 회귀 테스트를 단일 연속 문장 출력에 맞게 유지한다.
- HTML에 자막 텍스트 요소가 하나만 있고, CSS가 두 줄 높이·왼쪽 정렬·overflow 숨김을 보장하는지 검증한다.
- 서버 endpoint와 `CaptionUpdate` 계약에는 UI 줄 수나 문자열 누적 제한이 추가되지 않았음을 검증한다.
- README와 API/UI 구분 문서가 단일 연속 문단 정책과 개별 API 이벤트 정책을 혼동하지 않는지 검증한다.
- 전체 Node, .NET, PowerShell 테스트와 Release 빌드·포맷 검증을 통과해야 한다.

## 제외 범위

- 운영 방송 시스템의 실제 자막 sink 형식은 변경하지 않는다.
- API 응답을 하나의 누적 문자열 메시지로 바꾸지 않는다.
- 애니메이션 스크롤, 글자 크기 자동 축소, 말줄임표는 추가하지 않는다.
- 화자 분리, 단어 timestamp, confidence는 생성하지 않는다.
