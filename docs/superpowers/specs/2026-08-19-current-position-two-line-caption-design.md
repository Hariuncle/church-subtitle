# 현재 영상 위치 기반 2줄 자막 테스트 UI 설계

## 목표

로컬 테스트 UI에서 YouTube 영상을 원하는 위치로 이동한 뒤 `시작`을 누르면, 그 위치와 일치하는 전체 영상 PCM을 OpenAI 실시간 전사 API로 전송한다. 전사는 영상 끝 또는 사용자의 `중지`까지 계속되며, 화면에는 실제 송출 형태의 최근 2줄 자막만 표시한다.

운영 WebSocket API의 무제한 세션 동작과 메시지 규격은 변경하지 않는다. 이번 변경은 로컬 YouTube/PCM 테스트 UI와 테스트 음원 범위에만 적용한다.

## 음원 준비와 위치 매핑

- 권한이 확인된 원본 영상 `YLsWQq04R10`의 `00:00–24:26` 전체를 `24 kHz / 16-bit / mono PCM`으로 준비한다.
- 기존에 보관된 원본 미디어가 있으면 다시 다운로드하지 않고 재사용한다.
- PCM 기준 초당 바이트 수는 `48,000`이다.
- 시작 위치는 시작 버튼을 누른 순간 YouTube 플레이어의 `getCurrentTime()`으로 읽는다.
- PCM 시작 바이트는 `floor(videoSeconds * 48,000)`을 16-bit 샘플 경계와 4,800바이트 프레임 경계에 맞춰 내림 정렬한다.
- 서버는 전체 PCM 파일에 HTTP Range를 지원한다. 브라우저는 계산된 바이트부터 파일 끝까지만 요청한다.
- 영상은 선택한 위치에서 재생하고 PCM은 같은 기준 위치부터 100ms 프레임으로 실제 시간에 맞춰 전송한다.

## 세션 수명과 영상 제어

- 기존 고정 `09:25` 이동을 제거한다.
- 30초/2분/15분 실행 길이 선택을 제거한다.
- 전사는 다음 중 하나가 발생할 때까지 계속된다.
  - 사용자가 `중지`를 누름
  - 영상이 끝남
  - WebSocket 또는 OpenAI 공급자 오류
  - 영상과 PCM의 시간 차이가 허용 범위를 초과함
- 시작 클릭 시 YouTube 재생을 동기적으로 요청해 브라우저 자동재생 제한을 피한다.
- 세션 중 사용자가 다른 위치로 탐색하면 현재 세션을 안전하게 중지하고, 새 위치에서 다시 `시작`하도록 안내한다. 실행 중 임의 탐색을 자동으로 이어 붙이지 않는다.
- 일시정지나 버퍼링은 제한 시간 동안 기다리고, 재개되면 PCM 페이싱 기준을 이동해 따라간다.
- 무음도 PCM 프레임으로 계속 전송되므로 서버의 무입력 타임아웃에 걸리지 않는다.

## 2줄 자막 표시 규칙

자막 영역은 누적 기록 목록 대신 고정된 두 줄 송출 화면으로 변경한다.

- `partial`은 현재 발화 줄을 같은 `lineId`와 증가한 `revision`으로 갱신한다.
- 현재 partial이 있으면 위 줄에는 가장 최근 final, 아래 줄에는 partial을 표시한다.
- partial이 final이 되면 최근 final 목록에 추가하고, partial이 없을 때는 최근 final 두 개를 시간순으로 위·아래에 표시한다.
- 세 번째 final이 들어오면 가장 오래된 줄을 버리고 나머지를 위로 민다.
- 지연되거나 낮은 revision의 이벤트는 기존 watermark 규칙으로 무시한다.
- 세션 시작 시 두 줄을 초기화한다. 세션 종료 후에는 마지막 두 줄을 유지한다.
- 빈 줄은 레이아웃 높이를 유지해 화면이 흔들리지 않게 한다.

## UI 변경

- 헤더의 `원본 시작 09:25` 표기를 `현재 위치에서 시작` 안내로 바꾼다.
- 실행 길이 선택 필드를 제거한다.
- 확정 자막 기록 패널을 제거하고, 큰 글자의 2줄 자막 무대로 교체한다.
- 시작 버튼은 YouTube 플레이어와 전체 PCM이 준비된 뒤 활성화한다.
- 위치가 PCM 범위를 벗어나거나 남은 PCM이 없으면 API 세션을 열지 않고 안전한 한국어 오류를 표시한다.

## 오류 및 보안

- API 키는 기존과 같이 서버 프로세스 환경에서만 읽고 브라우저에 노출하지 않는다.
- 브라우저에는 키, 원시 OpenAI 오류, 스택 추적을 표시하지 않는다.
- HTTP Range가 유효하지 않거나 PCM 길이가 기대와 다르면 전사를 시작하지 않는다.
- 하나의 로컬 자막 세션만 허용하는 기존 서버 게이트를 유지한다.

## 테스트

- 임의 영상 시간에서 계산되는 PCM Range 시작 바이트와 프레임 정렬을 검증한다.
- 고정 565초 seek가 더 이상 발생하지 않고 현재 플레이어 위치가 사용되는지 검증한다.
- duration 제한 없이 영상 끝 또는 명시적 중지까지 PCM이 계속 전송되는지 검증한다.
- 시작 클릭의 동기 재생 요청, 초기 재생 대기, 버퍼링, drift 중단을 검증한다.
- partial/final/revision 조합에서 정확히 최근 두 줄만 유지되는지 검증한다.
- 세 번째 final이 첫 번째를 밀어내는지, partial이 아래 줄에서 갱신되는지 검증한다.
- 전체 .NET, Node UI, PowerShell 회귀 테스트와 Release 빌드/포맷 검증을 통과해야 한다.

## 제외 범위

- YouTube iframe의 오디오를 브라우저에서 직접 캡처하지 않는다.
- 실행 도중 사용자가 탐색한 새 위치로 동일 OpenAI 세션을 자동 재매핑하지 않는다.
- 운영 방송 시스템의 실제 오디오 입력 장치나 기존 자막 sink는 이번 변경에 포함하지 않는다.
- 화자 분리, 단어별 timestamp, confidence는 생성하지 않는다.
